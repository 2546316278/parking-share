## 目录重组为 backend / frontend / databases（11:44 完成）

用户要求按技术类型分类，新建 parking 式结构。最终落地：

```
shared-parking/
├── backend/
│   ├── vision/      视觉检测服务（原 vision/）
│   └── flask/       Flask 业务后端（原 server/，含 models/routes/services）
├── frontend/        （原 web/）

├── docs/ scripts/ tests/ experiments/
```

### 关键决定
- **没有**在 backend 下建 flask/springboot/fastapi 三套并列。理由：技术栈已定稿 Flask，
  另两套会永久空着；springboot 是 Java，与 Python 依赖体系不兼容。已向用户说明。
- **vision 没有塞进 flask**。理由：YOLO 模型加载慢会阻塞 Flask 启动；模型非线程安全；
  检测服务崩溃不应拖垮 Web。与 TECH_STACK.md 的 D1 决策一致。
  用户提到"把模型放 flask 里"，已解释，等他后续讲业务需求时再确认是否调整。

### 技术要点
- `backend/vision/config.py`：`BASE_DIR` 从 `VISION_DIR.parent` 改为 `VISION_DIR.parent.parent`
  （多嵌套一层），新增 `BACKEND_DIR`
- `scripts/make_demo.py` 的 `BASE_DIR` 不用改（scripts 仍在根目录下）

用户之前用 `scripts/convert_ccpd_to_yolo.py` 把 CCPD 转成 YOLO 格式并训练过。

### 数据集还在，位置变了
- 原 `D:/CCPD` 已不存在
- 转换后数据集在 **`D:/database/ccpd_yolo`**：train 159,996 / val 19,999 / test 20,001 张
- **CCPD 文件名编码真值**：`split('-')[4]` 是车牌字符码，可解码出真实车牌号 → 能直接算准确率
- 解码表：provinces 31 项、alphabets 去掉 I/O 的 24 个字母、ads = alphabets + 0~9

### 关键技术坑：torch 与 paddle 的 import 顺序

- ❌ 先 `import paddle` 再 `import torch` → `OSError: [WinError 127] 找不到指定的程序`
- ✅ 先 `import torch` 再 `import paddle` → 两者共存正常
- 原因：两框架各带一套 MKL/DLL，加载顺序错就冲突
- **plate.py 顶部固定写成 torch 在最前**，改动时必须保持

### 相对旧实现（license_plate_recognizer.py）的优化
1. 小尺寸车牌先放大再 OCR —— 实测 79x30 的裁剪 PaddleOCR 直接返回空串，放大 3x 才识别
2. OCR 空结果时 CLAHE 增强 + 3x 放大重试（救回部分逆光/低对比样本）
3. 分级检测阈值：0.35 检不到 → 0.12 重试（CCPD 困难样本在 0.35 下经常 0 检出）
4. 宽高比过滤 1.6~6.0 —— 低阈值兜底会把整个车身框成车牌（实测出现 720x436 的框）
5. 车牌号清洗：去 `·`、全角转半角、I→1、O→0
6. 格式校验：省份简称白名单 + 字母位 + 长度 7~8
7. 多帧投票 PlateVoter（窗口 8，最少 3 票）
8. 不在模块导入时初始化模型（旧代码有全局单例，import 就加载）
9. 抓拍存证到 `data/snapshots/`
