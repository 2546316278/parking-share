# 项目长期记忆 · shared-parking

> 毕设项目：基于视觉车位状态检测的共享车位预约分配系统
> 详细技术选型见 `docs/TECH_STACK.md`，目录约定见 `docs/STRUCTURE.md`

## 项目定位

用摄像头画面自动判断车位是否被占用，业主发布闲置时段，访客在线预约，系统用视觉检测做**自动核销**。
核心矛盾：「已预约但实际被他人占用」——这是整个系统要解决的问题，也是答辩重点。

## 硬约束（不可违反）

- **Python 3.9.24**（conda `yolov8_env`）：不能用 `X | Y` 联合类型注解、不能用 `match`
- **numpy 固定 1.26.4**，升级到 2.x 会让 `import cv2` 崩
- **不用 Redis**（第一阶段）：Windows 不支持，改用 MySQL 行锁 + 唯一索引防超卖
- **不做真实支付**：模拟下单，但订单状态机按真实流程设计
- **不碰旧项目 `D:/停车场`**：不复用其代码，旧项目存在明文密钥、零鉴权、单进程塞模型等问题

## 关键设计决策

- **D1 双进程**：`vision/` 独立进程跑检测写状态，`server/` Flask 只读状态。模型非线程安全，不能和 Web 塞一个进程
- **D2 双状态字段**：`physical_status`（视觉写，free/occupied）与 `business_status`（业务写，available/reserved/in_use/maintenance）**不可合并**，否则表达不了"已预约却被占"
- **D5 判定用面积重叠率**：不是距离。`coverage = 车辆框∩车位多边形面积 / 车位面积 ≥ 0.35` 判占用。一辆车贪心归属覆盖率最高的车位，避免斜停时两个车位同时判占用
- **时序平滑**：5 帧滑动窗口，≥3 票一致才切换，压掉单帧抖动和漏检
