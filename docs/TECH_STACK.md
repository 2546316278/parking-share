## 三、关键选型决策记录

### D1：视觉检测与业务后端拆分为两个独立进程

- **决策**：`backend/vision/` 为独立 Python 进程，读视频帧、跑 YOLO、写车位物理状态到数据库；`backend/springboot/` 为 Java 业务服务，只读状态、不碰视频流。两者不共享任何代码，只通过数据库表交换数据。
- **理由**：
  1. YOLOv8 是 Python 生态，无法在 JVM 内运行；强行用 HTTP 包一层只会增加故障点
  2. YOLO 模型加载需要数秒，塞进 Web 服务会拖慢启动
  3. 模型实例非线程安全，检测线程与请求线程共用一个实例会崩
  4. 检测服务崩溃不应导致网站不可用，反之亦然
- **代价**：需要保证两边表结构、字符集、时区一致，由 `databases/schema.sql` 统一约束。

### D2：车位状态采用双字段设计，不可合并

- **决策**：`spaces` 表同时维护 `physical_status`（视觉写入：free/occupied）与 `business_status`（业务写入：available/reserved/in_use/maintenance）。
- **理由**：单一 status 无法表达"已被预约但实际被他人占用"这类冲突，而该冲突正是自动核销逻辑的处理对象，也是本系统的设计核心。
- **约束**：视觉进程只能写 `physical_status`，业务进程不能直接改 `physical_status`，反之亦然。跨状态一致性由定时对账任务解决。

### D3：第一阶段不使用 Redis，用 MySQL 行锁保证预约不超卖

- **决策**：抢位使用 `SELECT ... FOR UPDATE` 配合 `(space_id, start_time, end_time)` 唯一约束；Redis 作为第二阶段可选优化。
- **理由**：Redis 官方不支持 Windows，本地部署会增加约半天环境成本；而"行锁 vs Redis 锁"的吞吐对比本身可作为论文的性能实验内容。
- **触发条件**：若并发压测显示行锁成为瓶颈，再引入 Redis 并保留原实现作为对照组。

### D4：支付采用模拟实现，但订单状态机按真实流程设计

- **决策**：不接入真实支付渠道，但订单状态完整实现 `pending → paid → in_use → completed` 及 `cancelled / refunded / violated`。
- **理由**：任务书要求"模拟支付下单"；完整状态机可支撑后续扩展，且状态流转本身是系统设计章节的内容。

### D5：车位检测采用"ROI 覆盖率 + 车辆唯一归属"判定

- **决策**：先标定车位多边形，每帧做车辆检测，计算车辆框落在车位多边形内的面积占比，超过阈值判为占用；同一辆车只归属覆盖率最高的车位。
- **理由**：相较训练车位分类模型，该方案不需为每个车位准备样本，冷启动成本低，且可解释性强（能输出覆盖率数值用于调试与答辩演示）。
- **补充**：PKLot 数据集上的分类模型作为**对比实验**保留在 `experiments/`，用于论文的算法对比章节，不进入主链路。

### D6：业务模式严格按任务书执行——业主发布空闲时段

- **决策**：车位归属**业主**（个人），业主自行发布可预约时段与价格，访客按时段预约。不做"车位全属物业、任意车辆可临停"的模式。
- **理由**：任务书的核心是"**共享**车位"——业主把私车位闲置时段拿出来共用。若改成物业统一管理、任意车辆可临停，则"共享"这一立论基础消失，与选题不符。
- **影响**：
  - `spaces` 表需含 `owner_id`，车位与业主为多对一
  - 新增"可预约时段"实体（发布记录），承载时段、价格、状态
  - 未发布的时段，车位即便空着也不对外开放
  - 前端需有"我的车位 / 发布时段"入口

### D7：明确不做车牌识别

- **决策**：不做车牌识别、人员身份识别、车辆轨迹追踪。
- **理由**：任务书"研究对象与边界界定"一节明确排除这三项。视觉检测的定位是**状态感知辅助**，预约冲突以业务规则校验为准。
- **注**：曾实现过一版车牌识别（git 历史 `079b2f8`），按任务书要求已移除，不再作为主链路的一部分。

## 七、明确不采用的技术

| 技术 | 原因 |
|---|---|
| 车牌识别（PaddleOCR / HyperLPR3） | 任务书边界明确排除，见决策 D7 |
| 讯飞人脸登录 | 涉及人脸数据合规风险，且与选题无关 |
| Q-Learning 自适应参数 | 旧项目内容，与本选题无关 |
| NL→SQL 智能助手（Ollama） | 存在 SQL 注入面，且与选题无关 |
| 原生 HTML 多页 + 全局函数 | 页面数量增加后维护成本陡增 |
| `setInterval` 轮询 base64 帧 | 带宽与 CPU 浪费严重，改用 MJPEG 流或前端拉快照 |
| Redis 分布式锁（第一阶段） | 见决策 D3 |
| Flask / FastAPI | 任务书指定 Spring Boot |
